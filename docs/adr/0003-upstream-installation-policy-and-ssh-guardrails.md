# 跟随上游安装策略，同时保留 SSH 权限门槛

上游新版已将安装配置改为自动补齐缺失项，并将普通组件的版本检查改为提示。此次 SSH 贡献选择沿用这些行为，避免在共享安装器上长期维护两套流程；SSH 所需的原生权限能力不属于可忽略的兼容提示，因此单独保留严格门槛。

## 已确认的取舍

- 本次交付为上游新版加独立 SSH 扩展的贡献分支，不包含个人 quota 修改；已有 quota 提交独立保留，不丢弃。
- 安装器按上游策略自动补充缺失的配置条目和键，保留用户已有的 Provider、模型、权限、插件选项及注释；有实际写入时先备份。不恢复默认要求手工合并的旧流程。
- 普通组件沿用上游版本提示策略。显式选择 SSH 时仍要求 OpenCode 2.0.31+，不能把版本不足当作普通警告继续安装；`--all`／`--without` 隐式包含 SSH 时，版本不足应跳过 SSH 并继续其余组，不能把门槛扩散到其他组件。插件启动时必须检查实际的 `permission.assert` 能力，缺失时拒绝加载，不能降级放行。
- 整合实施时允许对 README 做必要的冲突融合和最小说明更新：保留上游新版结构、风格及功能介绍，补充 SSH 介绍、安装要求和说明入口。本分支不再随包分发三份独立 SSH 教程（`ssh_use.md`、`ssh_usage.md`、`ssh_first_time_setup.md`）；相关安装、连接与限制说明由插件 README 承载，删除同时清理打包与安装引用。不单独重写 README 或改写其他插件的介绍。
- 模拟权限、静态检查和真实运行分别报告；普通组件的警告不等于兼容性已获验收。

本 ADR 记录决策，不表示实施完成或发布授权；是否推送、安装或重启服务以实际执行记录为准。相关配置行为只通过隔离安装验证，不修改真实全局配置。

## 未采用的方案

不在 SSH 贡献分支中夹带个人 quota 改动；不为 SSH 恢复整套旧安装器；不把上游“版本不足只警告”的策略扩展为 SSH 权限能力缺失时仍继续运行。

与既有独立插件、角色及权限边界的设计保持一致。这里的上游对齐是此次版本整合决策，不是对旧版行为的逐字节保留承诺。
