# ADR 0002：隔离 opencode-quota-zh 命名空间并将其作为原版替代品

## 状态

已接受

## 背景

`opencode-quota-zh` 是从上游 `opencode-quota` 移植并中文化的插件。当前实现虽然已有独立目录和部分插件标识，但仍在进程全局键、telemetry、配置、凭证缓存、状态文件、导出、CLI 安装更新逻辑和日志文案中沿用上游命名。两者同时存在时可能互相覆盖状态、吞掉命令处理、重复注册界面，甚至让中文版的更新命令操作上游包。

完全支持两个插件同时启用还需要复制并改名 `/quota` 等所有用户命令，同时会产生重复 Provider 查询和重复界面，没有足够产品价值。

## 决策

- `opencode-quota-zh` 作为原版 `opencode-quota` 的替代品，而不是可同时启用的第二份额度插件。
- 保留 `/quota`、`/quota_status`、`/tokens_*` 等用户命令名称。
- 检测到原版和中文版同时启用时明确报告冲突，并要求用户二选一。
- 中文版自身拥有独立的插件标识、进程全局键、telemetry、配置目录、非共享缓存、应用状态、凭证缓存、导出、CLI、安装更新目标和日志前缀。
- 中文版主配置路径为 `opencode-quota-zh/config.jsonc`。
- 法律归属、上游引用和 OpenCode 的共享会话数据库不改名。
- 只有被明确建模为跨插件共享的数据才可使用中立的共享命名空间；不得以 `opencode-quota` 上游命名空间作为隐式共享机制。
- 旧命名空间通过一次性迁移处理：用户配置和本地累计状态迁入 `opencode-quota-zh`，可重建缓存不迁移，正常运行时不回退读取旧目录。
- models.dev 价格快照是明确的跨插件共享资源，迁入 `~/.cache/opencode/modelsdev-pricing/`；该目录只保存版本化价格快照和刷新状态，不保存凭证、额度状态或告警状态。

## 后果

### 正面

- 中文版不会再误读、覆盖或更新上游插件的私有运行状态。
- 插件来源在诊断、日志和 telemetry 中可明确区分。
- 用户保留熟悉的命令，不承担无价值的 `_zh` 命令后缀。
- 共享资源必须显式定义，冲突更容易审查和测试。

### 负面

- 已有中文版用户需要迁移旧的配置和状态路径。
- 不能把原版和中文版同时启用作为受支持场景。
- 安装器和诊断需要新增冲突检测与迁移说明。
- 迁移工具必须保留用户文件权限，默认不删除旧文件，并在迁移后提示用户确认清理。

## 被否决的方案

### 完全支持原版与中文版同时启用

否决原因：需要重命名全部用户命令，并导致重复额度查询、重复侧边栏和双份维护成本。

### 继续共享上游命名空间

否决原因：共享不是显式接口，已经造成全局键、凭证缓存、导出和安装更新目标的真实冲突风险。
