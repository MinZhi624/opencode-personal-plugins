# ADR 0001：以启动提示和额度告警取代例行额度弹窗

## 状态

已接受

## 背景

`opencode-quota-zh` 当前把普通额度摘要作为 toast，在会话空闲、`question` 工具结束和会话压缩后主动展示。该行为会重复打断用户，也把正常额度信息与真正需要处理的额度危险状态混为一谈。

现有配置以 `quotaToast`、`enableToast` 和多个 `showOn...` 字段描述这些触发事件。继续扩展这组字段会迫使用户理解内部生命周期事件，并让新的危险告警与旧的例行弹窗长期共用一套含混接口。

## 决策

采用“被动额度展示 + 状态转换驱动的额度告警”模型：

- 正常额度默认只通过启动提示、侧边栏和用户主动调用的 `/quota` 展示；用户可以显式开启会话输入框下方的 prompt bar 作为唯一可选被动表面。
- 会话空闲、工具完成和会话压缩不再产生例行额度弹窗。
- 只有额度进入配置定义的危险状态时，才允许产生主动额度告警。
- 告警以 Provider、账户和额度窗口的告警周期去重，默认每周期一次；用户可显式配置低频重复提醒。
- 启动提示与额度告警使用独立的新配置接口。
- prompt bar 使用独立的显式开关并默认关闭；安装器和迁移流程不得自动开启。
- 插件主配置统一为 `opencode-quota-zh/config.jsonc`；工作区可用同一相对路径覆盖全局配置。
- 删除旧的 `experimental.quotaToast` 和 `opencode-quota/quota-toast.json(c)` 运行时配置入口；诊断命令只负责识别并提示迁移。
- 删除旧的 `enableToast`、`showOnIdle`、`showOnQuestion`、`showOnCompact` 和 `showOnBothFail` 字段，不保留运行时兼容分支。
- 检测到旧字段时明确报告迁移要求，不静默忽略。
- 该变更作为插件主版本的不兼容升级发布。

新配置的用户接口限定为：

```jsonc
{
  "startupHint": {
    "enabled": true
  },
  "promptBar": {
    "enabled": false
  },
  "alerts": {
    "enabled": true,
    "percentRemainingThreshold": 0,
    "repeatAfterMinutes": null,
    "balanceThresholds": {
      "deepseek": {
        "CNY": 2,
        "USD": 0.5
      }
    }
  }
}
```

`percentRemainingThreshold` 和货币余额阈值均按当前值小于或等于阈值触发。`repeatAfterMinutes: null` 表示本告警周期不重复；非空值必须是至少 15 的整数分钟。Provider 明确报告不可用时始终可触发告警。缺失、未知、查询失败和合成占位数据不得触发或恢复告警。账户识别、周期去重、同批合并、严重级判断和持久化都属于告警模块内部实现，不扩张用户配置接口。

只有 TUI 成功接受告警后才记录为已提醒；显示失败不消耗该告警周期的提醒机会，并在后续既有额度刷新点重试。告警状态保留到额度可靠恢复、重置或用户主动执行 `/quota_alerts reset`。

prompt bar 仅在用户显式开启后显示当前会话模型对应 Provider 的一个最相关百分比窗口，优先短周期或最早重置窗口；内容限定为 Provider、剩余百分比和重置倒计时。没有可靠模型匹配或数据未知时不渲染。

## 后果

### 正面

- 默认体验低干扰，自动弹窗只表达需要用户处理的危险状态。
- 配置接口围绕用户领域概念，而不是 OpenCode 内部事件。
- 告警阈值、去重和 Provider 差异可以集中在一个深模块中实现与测试。
- 不需要长期维护新旧两套通知语义。

### 负面

- 现有用户必须迁移旧配置。
- 安装器、示例配置、诊断输出和文档必须同步升级。
- 插件需要新增持久化告警状态和配置校验。

## 被否决的方案

### 保留旧字段并映射到新告警

否决原因：旧字段表达的是生命周期触发事件，不足以表达危险阈值、告警周期和重复策略；映射会产生含混语义。

### 只修改默认值，继续保留例行 toast 能力

否决原因：虽然兼容性更好，但会让项目长期保留与“平时安静”原则冲突的产品路径和测试负担。
